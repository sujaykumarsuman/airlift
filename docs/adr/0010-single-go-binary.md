# ADR 0010 — One Go binary; the Python sender is retired

Status: accepted (Phase 5, prompt 002)

## Context

Prompt 001 split the project across languages: a Python sender (`airlift.py`,
depending on `segno`) and `tools/repobundle.py` ran inside the air gap, while a
Go tower ran on the laptop. The air-gapped machine therefore needed a Python
runtime and a third-party package present or vendored, and the beam encoder,
the frame codec and the repobundle format each existed twice. Prompt 002 makes
the tower a hosted, multi-user service and wants the air-gapped side to be a
single static binary with nothing to install.

## Decision

There is one program, `cmd/airlift`, a single static binary. Its **user-facing
surface is two subcommands**, only what a transfer needs:

- **`beam PATH…`** — turns the input into a named, self-contained QR page and
  opens it in the browser. One folder is bundled (git-aware); one file is sent
  as-is; several files are bundled and require a name (`--name`, a `name:` line
  in `--files-from`, or a prompt on a terminal). Every beam has a name, so a
  session can list several by name.
- **`tower`** — hosts the airlift server (config-driven `~/.airlift` and
  preflight land in Phase 6).

Everything else is an **internal process, not a subcommand**: bundling
(`internal/bundle`), the encoder, QR rendering and HTML player
(`internal/beam`), reassembly/decode (`internal/beam.Decode`), and the dev
replay (`internal/replay`). There is no `pack`, `unpack`, `frames`, `decode` or
`replay` command, and no `beam.json` frames-dump artifact on the user's disk;
those exist only as library calls the tests drive. Receiving-side downloads are
served by the tower's session dashboard, not a CLI. `cmd/tower` is removed;
`make airlift-all` cross-compiles the binary for darwin, linux and windows on
amd64 and arm64, and the release workflow attaches those binaries and nothing
else.

**Fountain is automatic, never a flag.** `beam` runs `ModeAuto`, which uses a
sequential loop for small payloads and switches to fountain once the chunk
count reaches a threshold, where the last-chunk problem and the multi-scanner
speed-up pay for the packet overhead. The user never chooses a mode.

`sender/airlift.py` and `tools/repobundle.py` are deleted. Their behaviour
moves into Go:

- The encoder (gzip → chunk → frame, both layouts) lives in `internal/beam` and
  is shared by `beam` and `internal/replay`. The QR rendering and the HTML
  player move there too; the player template is the Python one verbatim,
  emitted from Go.
- Bundling is a byte-for-byte port of `repobundle.py pack` in `internal/bundle`;
  the four committed bundles under `testdata/bundles/` are the contract that
  let the script be deleted, and the format is written down in `docs/BUNDLE.md`.
- The frozen fixtures `vectors.json` and `vectors-fountain.json`, generated by
  the Python sender and never regenerated from Go, move to `testdata/vectors/`
  and stay the cross-implementation contract for the frame and fountain
  formats, exercised through the internal packages. `internal/proto` is now
  their reference implementation.

The gate drops `ruff`/`pytest`/`uv`; it is `gofmt` + `go vet` + `go test` for
Go and `tsc` + `eslint` + `vitest` for the web UI. The end-to-end (bundle →
beam → replay through loss → READY → the tree restored) runs inside `go test`.

## Consequences

- The air-gapped machine needs only the `airlift` binary — no Python, no
  `segno`, no vendored package — and the operator learns two commands. The beam
  is still one self-contained offline HTML file (ADR 0003 holds); only the
  emitter changed language.
- The frames dump, standalone decode and replay remain as internal machinery
  (the dev loop and the tests), so nothing is lost by hiding them; they can be
  re-exposed cheaply if a real use appears.
- Go's gzip stream differs from Python's, so Go's frames are not byte-identical
  to the old sender's. Both are self-consistent and verified against the
  manifest hashes, and for the multi fixture both land on the same chunk count,
  so the frozen fountain index sets still match.
- The seeded sender-session id is deterministic within Go but no longer matches
  Python's Mersenne Twister; nothing depends on the value, only on its being
  stable for a given seed.
- One codebase, one test suite, one release artifact set. The cross-language
  duplication and its drift risk are gone.
