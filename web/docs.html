Using airlift

airlift moves a file out of a machine that has no network at all. The machine shows the file as an animated QR loop; a phone reads the loop and relays it to a tower on the internet, which puts the file back together, checks it, and lets you download it. Nothing crosses the gap but light.

BeamOne self-contained HTML page made by airlift beam. It never talks to anything — that is what keeps the air gap.
TowerThis site. It hosts sessions, receives frames, verifies the sha256 chain, unpacks a repobundle and serves downloads.
DashboardA session's shared page: share the link, watch beams land, download results. Everyone who joins sees the same thing.
ScannerThe camera page a phone opens from the dashboard's Scan a beam. It stops itself once the beam is in.

Install the CLI

You need the airlift binary on the air-gapped machine (to make beams) — copy it in however files normally get in there. The tower side is already hosted; nothing to install.

Download a release

Pick your platform from the latest release, then make it executable and put it on your path:

curl -LO https://github.com/sujaykumarsuman/airlift/releases/latest/download/airlift-darwin-arm64 chmod +x airlift-darwin-arm64 && sudo mv airlift-darwin-arm64 /usr/local/bin/airlift

Assets: airlift-darwin-arm64, airlift-darwin-amd64, airlift-linux-amd64, airlift-linux-arm64, airlift-windows-amd64.exe, plus SHA256SUMS. On macOS, if Gatekeeper objects: xattr -d com.apple.quarantine airlift.

Or with Go

go install github.com/sujaykumarsuman/airlift/cmd/airlift@latest

Or from source

git clone https://github.com/sujaykumarsuman/airlift.git && cd airlift && make airlift # → bin/airlift

Needs Go 1.26 and Node (the web UI is embedded into the binary). airlift --help should then list the two commands, beam and tower.

Make a beam

On the air-gapped machine, point airlift beam at what you want out. It bundles, compresses, chunks the payload into QR frames and writes one self-contained HTML file — the frames as text plus a small encoder that draws each code in the page, so the file is about one and a half to two times the compressed payload — then opens it in the browser.

A folder

airlift beam ./my-repo

The folder becomes a repobundle — git-aware, so .gitignore is respected — named after the folder. The tower unpacks it back into a tree and offers it as a zip.

A single file

airlift beam ./notes.txt

Sent as-is, named after the file; the tower serves it back as the raw file.

Several files

airlift beam --name evidence report.pdf photo.jpg log.txt

Several paths are bundled together and need a name — --name, or a name: line in a list file:

airlift beam --files-from list.txt # list.txt: "name: evidence" then one path per line

What it prints

  bundle   text format
  gzip          34158 bytes   39.3 % of input
  chunks           27 × 1311 bytes
  mode     fountain (79 packets, LT/robust soliton)
  qr       version 30 (137×137 modules), ECC M, alphanumeric
  loop             83 frames   manifest every 20   8.3 s per pass at 10 fps
  session  0x59e7812e
  output   179.0 KB   built in 4 ms

Small beams (under 24 chunks) play their chunks in order and repeat; larger ones switch to a fountain code automatically, so every pass produces fresh packets and a missed frame never means waiting for the same one to come round. The mode is picked from the size unless --mode says otherwise.

Options

--name NAMEThe beam's name (the tower shows it). Required for several files.
--fps NInitial frames per second, 1–60 (default 10). Raise it once the scanner reports more decoded/s than that; 12 and 15 sit cleanly on a 60 Hz screen.
--chunk BYTESPayload bytes per frame (default: what QR version 30 holds at --ecc, 1311 at M; at most 2712 — and 2712 when sending with -s). Bigger chunks mean fewer frames but denser codes.
--version-target VPick the largest chunk that fits QR version V (1–40) instead of --chunk.
--ecc L|M|Q|HQR error correction (default M). Higher survives glare better, at fewer bytes per frame.
--manifest-every KRe-insert the manifest frame every K frames (default 20), so a scanner that starts mid-loop learns the beam quickly.
--format auto|text|base64Bundle format for folders. auto (the default) bundles as text — about 30 % less to send — when every file is text and none holds a boundary marker, else as base64.
--mode auto|sequential|fountainFrame layout. auto (the default) is sequential under 24 chunks and fountain from there (always sequential with -s, where nothing is lost); sequential gives the smallest page and a fixed pass, fountain shrugs off lost frames and lets two phones share the work.
--out FILE · --no-openWhere to write the page (default <name>.html), and whether to open it.
-s LINK · --to-session LINKSkip the page and send straight to the session at LINK — only from a machine that is not air-gapped. See Send directly.
--wait DURATIONWith -s: how long to wait for a session admin to let you in and to approve the upload (default 3m).

Leave out the path on a terminal — just airlift beam — and it asks what to beam and where; several files without --name are asked for a name. In a script nothing is asked: a missing input is an error naming the flag.

Show it

Open the HTML on the air-gapped screen. The page is black with only the code bright, so a camera exposes for the QR; make it full-screen and leave it playing.

  • Size — [ / ] scale the code 40–100 %. Smaller can decode better when the phone is close and the screen is large.
  • Speed — + / − change the fps live. Watch the scanner's decoded/s; run the beam a touch below it.
  • Chrome — h hides everything but the code; f goes full-screen.

Receive it

  1. Create a session on the tower's home page (a join password is optional; tick Joiners are session admins if you want everyone to be able to end it).
  2. Open the session on the phone — scan the QR on the dashboard or open the link. The phone joins the same session and sees the same dashboard.
  3. Tap Scan a beam and point the camera at the screen. The HUD counts chunks as they land — one tally mark per chunk, a minimap of pages, and the decode rate. The scanner stops itself and offers to close once the beam is whole.
  4. Watch the dashboard. Each beam is a card: chunk marks while receiving, then the verification — gzip sha256, original sha256, every file's sha256 — and the downloads: the raw file, or the unpacked tree as a zip.

Send directly

When the machine with the files is on a network, the page, the screen and the camera are overhead. Give airlift beam the session's link instead:

airlift beam ./my-repo -s 'https://projects.sujaykumar.dev/airlift/qkf-mzt-bwp#t=…'

It bundles and checks the payload exactly as for a page, joins the session as a sender and asks leave to upload. Quote the link — the # and & in it mean something to a shell.

  • Getting in. A share link carries the session's token, so it joins at once. A password session's link (the id alone) makes it ask for the password, typed without echo. A public session's bare id makes it knock, and it waits for a session admin to let it in.
  • Approval. Session admins see the beam's name, size and chunk count under Upload requests on the dashboard, with Approve and Deny; the sender shows among the participants with a sender tag while it waits. An approval admits exactly the beam that was described, once. A sender that is itself a session admin is approved at once.
  • Waiting. The CLI counts down --wait (default 3 minutes). If the run ends early for any reason — nobody decides in time, Ctrl-C, a lost connection — it withdraws the request and any half-sent beam is discarded, so nothing is left for an admin to approve.
  • Sending. A progress bar shows frames sent, the rate and the time left; then the tower verifies the sha256 chain and unpacks the bundle, and the CLI prints the verdicts and the dashboard link to download from. It exits 0 only when the beam is READY.

  bundle   text format
  gzip          34158 bytes   39.3 % of input
  chunks           13 × 2712 bytes
  mode     sequential
  tower    127.0.0.1:8797 (v0.1.6-dirty) · session frc-fuz-dob
  access   share link · you are "clever swift"
  approval approved by nimble sparrow
  sent     14 frames · 33.4 KB in 2 ms (13.2 MB/s)
  verify   gzip sha256 ok · input sha256 ok · bundle ok (23 files, 82.4 KB)
  ready    beam 94b68ddc "adr" — download it from http://127.0.0.1:8797/frc-fuz-dob

The approval gives a session's admins the say over what the command line adds; it is not a lock — anyone holding the session's link can already relay frames, as a phone's scanner does. And this is for connected machines only: on an air-gapped machine the page is still the way out — nothing there can reach a tower, and it never tries.

Sessions & people

  • A public session's link carries its token — anyone with the link is in. A password session's link is the id alone; joiners enter the password. Someone with only the id can knock, and a session admin admits or denies them.
  • Participants are devices: your laptop and your phone are two entries, each with its roles (viewer, relay, or sender for a CLI sending directly). A session admin can evict one. A sender leaves the list once its run ends.
  • Lifetime — a session stays alive while anyone is connected, up to 24 h; the last 30 minutes show a countdown and a +1 h for admins. If everyone leaves for 30 minutes it is suspended: opening its link reopens it. End session keeps the downloads for an hour; Delete now removes everything at once. Both live under the ⏻ menu in the nav.

Tips & troubleshooting

  • Distance and size. Fill the viewfinder with the code without touching its edges. If decodes stall, shrink the code ([) rather than backing the phone away.
  • Glare and light. A dark room and a matte screen decode best; the page is already black for that reason. Tilt the screen a few degrees if a reflection sits on the code.
  • The counters. new is frames the tower had not seen; dup is repeats (normal — the loop repeats); bad means a frame decoded but did not parse, usually motion blur — hold still.
  • Missing chunks. A sequential beam fills them on its next pass; a fountain beam keeps producing new packets, so just keep pointing. The minimap shows which pages are still short.
  • "Already received". The scanner tells you when the loop on screen is a beam the session already has. Show the next beam, or start a new session.
  • Several beams, one session. A session holds many beams; beam a folder, then a file, then another folder — each lands as its own card.
